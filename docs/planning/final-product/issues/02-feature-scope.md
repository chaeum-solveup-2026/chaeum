# 02: 본선 제품의 기능 범위

Type: grilling
Status: resolved
Blocked by: 01

## Question

chaeum-poc docs/RESOURCES.md 의 기능 지도에서 본선 제품에 넣을 기능과 뺄 기능은 무엇인가? 배점(완성도 25, 확장성 25, 유용성 25)과 적대적 리뷰에서 살아남은 차별점(입력 마찰 제거, 평시 재사용)을 기준으로 정한다.

## Answer

2026-10-28 grilling 으로 결정(찬규님). MVP 완성이 최우선이다.

MVP 범위:
- 기본(PoC 에서 검증): 엑셀과 문장 해석, 확인 큐와 보류, 부족 목록, 수령 확인, 기부자 공개 페이지, 공개 API 와 엑셀 내보내기, 현황판 차트, 담당자 인증
- 배정 단계: 상태를 요청 -> 배정 -> 수령으로 늘리고 부족 = 요청 - 배정 - 수령. 배송 중은 단순 상태 하나. 송장 연동과 택배 추적은 넣지 않는다
- 기부 전 확인(목업 S5, Offer 축): 기부자가 문장으로 적은 물품을 같은 해석기로 나눠, 부족한 품목은 기부 약속(= 배정)으로 진행하고 충분하거나 목록에 없는 품목은 보류 후 다른 지역이나 현금 기부를 안내
- 평시 모드(목업 S8), 최소 범위: 대피소 대신 배분 거점(자원봉사센터, 가구 코드)을 같은 모델로 다루고 폭염 냉방 물품 시나리오 하나를 시연
- 입력 경로: PWA 오프라인 기록은 넣는다. 문자는 실제 수신 없이 문자 형식(#A12 물50) 해석과 테스트 입력창까지
- 현황판에 대피소 위치 지도(15139148 위경도)

여유가 있으면(MVP 뒤): 분류 모델(C안). 조사(05) 권고대로 규칙 보강 -> 소형 모델 -> 사이드카 순으로 검토. 없으면 슬롯과 로드맵만 발표에 둔다.

범위 밖: 카카오톡 채널 챗봇(발표의 확장성 로드맵으로만), 실제 문자 수신 서비스, 송장 연동과 택배 추적, 기상특보와 산불위험 레이어, 정부 비축 재고 대조.
