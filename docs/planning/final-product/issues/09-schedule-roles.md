## Question

본선 진출 통보부터 12월 초 본선까지의 개발 일정(주 단위)과 찬규님, 성은님의 역할 분담은? 상세기획서에 넣을 일정(설계 이번 주 완료 목표, 저장소와 개발 환경 구성 이번 주 착수)과 맞춘다.

## Answer

2026-10-28 grilling 으로 결정(찬규님).

일정(주차는 본선 진출 통보일 기준):
- W0 (10/26~통보 전): 저장소와 개발 환경 구성 착수(이번 주 시작). Next.js + Spring 뼈대, docker compose, GitHub Actions + NCP 자체 실행기, 테라폼 코드 작성. 11/03 부터 협력 기관 접촉, 대피소 API 이용신청
- W1: 첫 tracer bullet 을 실제 배포까지(담당자 로그인 + 데모 시드 + 문장과 엑셀 입력 -> 해석 -> 확인 화면 -> 부족 목록 -> 공개 목록). NCP 자원은 테라폼 코드대로 콘솔에서 생성. 이후 기능은 항상 배포 가능한 상태에서 하나씩 더한다
- 11/17 2차 교류회: W1 결과를 실제 주소로 시연하고 멘토링 피드백으로 W2~W3 우선순위를 다시 본다
- W2: 배정, 기부 전 확인, 조건부 배정과 만료, 수령, 현황판과 대피소 지도, 15139148 수집
- W3: PWA 오프라인, 문자 형식, 평시 모드, 사용성 테스트(5명 이상) + SUS
- 본선 직전 3~4일: 발표자료, 시연 녹화, 질의 대비 한 장, 리허설. 여유가 있으면 분류 모델
- 늦어지면 빼는 순서: 분류 모델 -> 평시 모드(목업 영상으로 대체) -> 문자 형식 -> 대피소 지도. 입력 해석, 확인, 배정, 기부 전 확인, 수령, 공개 목록, 배포는 끝까지 지킨다. PWA 오프라인은 빼지 않고 안 되면 녹화 클립 범위로 줄인다

역할과 작업 방식:
- 작업은 작게 쪼갠 티켓을 순서대로 큐에 넣고, 손이 빈 사람이 막히지 않은 다음 티켓을 아무나 가져가는 방식(pull)으로 한다. 기본 담당 영역은 찬규님 백엔드(Spring, 해석기, 상태 모델)와 인프라(테라폼, CI/CD), 성은님 프론트엔드(Next.js, 목업 이식, PWA)와 사용자 쪽(기관 접촉, 사용성 테스트, 정답 표 검수)이지만 큐의 순서가 우선한다
- 예외로 사람이 정해진 티켓: NCP 콘솔 작업(대표자 찬규님만 접속 가능), 정답 표 검수(해석기를 만들지 않은 성은님)
- 이 방식을 위해 /to-tickets 는 티켓을 하루 안쪽 크기로 쪼개고 막는 관계(Blocked by)와 "담당 지정 여부"를 적는다. 둘이 같은 큐를 보려면 트래커를 GitHub Issues(+ 프로젝트 보드)로 옮겨야 하므로, 성은님 저장소 접근이 확인되면 setup-matt-pocock-skills 로 전환한다
- 발표자료는 함께 만들고 발표자는 나중에 정한다
- 리듬: 스크럼 주 2회 유지, 티켓 하나에 에이전트 하나 + tdd + 가벼운 게이트, 다관점 리뷰는 W1 끝, W2 끝, 본선 직전 세 번
