# 지도: 본선 제품 개발 계획

Label: wayfinder:map

## Destination

본선 제품(12월 초 본선 시연과 "서비스 개발 결과물" 제출 대상)의 기능 범위, 아키텍처, 배포 구성, 시범 사용자 계획, 일정이 결정되어, 곧바로 `/to-spec` 과 `/to-tickets` 로 넘겨 개발을 시작할 수 있는 상태.

## Notes

- 영역: 재난 구호 연계 서비스. 용어는 이 저장소 GLOSSARY.md, 예선 쪽은 chaeum-poc/GLOSSARY.md
- 출발 자료: chaeum-poc 의 docs/RESOURCES.md (PoC, 기획 문서, 경쟁 선례, 데이터, 기능 지도)
- 본선 사실(2026-10-28 확인): 예선 심사 11/04~06, 2차 교류회 11/17 (예선 합격자), 본선 12월 초, 발표 10분 + 질의 10분 + 서비스 시연. 배점 완성도 25, 확장성 25, 유용성 25, 기획성 15, 발표 10. 클라우드(Naver, KT, NHN) 무료, 수상자는 2027-12 까지 연장
- 일정 원칙: 결정 티켓은 예선 제출 전후로 진행하고, 상세기획서에는 "설계 이번 주(10/26~11/01) 완료 목표, 저장소와 개발 환경 구성 이번 주 착수"로 적는다(계획으로 쓰고, 끝나지 않은 일을 완료로 쓰지 않는다). 개발 코드는 본선 진출 통보 뒤 약 3주
- 우선순위: 배점상 실제 배포(완성도)와 시범 사용자(유용성)를 기능 추가보다 앞에 둔다
- PoC 자산: 테스트 자산(정답 표, 합성 엑셀, 품목 사전, 대피소 데이터)은 그대로 가져오고, 코드는 tdd 로 새로 쓰되 해석기 로직은 테스트와 함께 옮겨 와도 된다
- 디자인 원칙: 웹 화면은 SaaS 레이아웃(랜딩 6섹션 등)과 블로그 디자인 시스템(chan99k-blog DESIGN.md)을 따른다. 휴대폰 화면(PWA)은 성은님 HTML 목업의 동작과 휴대폰 화면 스타일을 보존하되(단, 신뢰도 수치는 화면에 보이지 않게 한다), 디자인 시스템의 공통 철학(토큰, 타이포, 카드)을 따른다
- 사람: 지도를 이끄는 사람은 찬규님. 성은님은 기획, 화면 결정 grilling 에 참여. 트래커는 로컬 마크다운, 성은님 공유 저장소 접근이 확인되면 GitHub Issues 로 옮긴다
- 결정 일정(10/28 확정, 설계는 이번 주 완료 목표): 10/28 01 회고, 10/28~29 10 배정 CSP 확인과 11 대피소 API 이용신청(사람 작업), 10/29 02 기능 범위와 07 시범 사용자, 10/30 03 아키텍처(10 결과 필요, 예선 1차본 마감일), 10/31 08 시연과 09 개발 일정, 11/01 지도 완료 후 /to-spec, /to-tickets. 밀리면 예선 기획서 일정 문구는 이 지도의 일정 원칙만으로 쓴다
- 세션마다 참고할 스킬: grilling, domain-modeling (기본), research (조사 티켓), prototype (화면이나 동작 결정)

## Decisions so far

<!-- 닫힌 티켓마다 한 줄: [제목](issues/NN-slug.md): 요지 -->

- [PoC 회고: 무엇이 잘 됐고 무엇을 버릴까](issues/01-poc-retro.md): 해석기 자산은 옮기되 test 세트는 마일스톤에만, 정답 표는 성은님 검수. 화면은 목업 구조 먼저, 인증과 데모 시드는 첫 슬라이스, 리뷰는 마일스톤 1라운드. 2단계 상태, 분류 모델, 배포는 02, 03 에서 다시 정함
- [본선 제품의 기능 범위](issues/02-feature-scope.md): MVP = PoC 기본 + 배정 단계 + 기부 전 확인 + 평시 모드(최소) + PWA 오프라인 + 문자 형식 해석 + 대피소 지도. 분류 모델은 MVP 뒤 여유가 있으면
- [시범 사용자와 유용성 지표](issues/07-pilot-users-metrics.md): 기관 1곳 목표, 최소 현장 경험자 5명 테스트. 11/03부터 연수구 재난안전 부서와 자원봉사센터 접촉. 지표는 SUS, 작업 시간 기준값, 실제 문장 F1. 예상 사용자 수는 시설 수 기반 산출, 테스트는 가상 데이터만
- [PoC 용어집 검토와 본선 용어 확정](issues/12-glossary-review.md): 확인 단계는 자동 반영, 확인 권장, 확인 필수(수치는 화면에 숨김). 보류는 기부 쪽만, 남은 수량은 부족 수량, 상위 용어 현장. 설계 용어는 ADR 로
- [상태 모델: 요청, 배정, 기부 약속, 배송 중, 수령, 보류, 배분 거점](issues/13-state-model.md): 품목 줄은 수량(요청, 배정, 수령)만, 상태는 배정 단위(약속됨, 배송 중, 수령 완료, 취소). 기부 약속은 즉시 조건부 배정 + 만료. 현장 유형으로 평시 공존. 오프라인은 기기 키로 중복 제거
- [아키텍처와 스택](issues/03-architecture-stack.md): Next.js 웹 + Spring Boot JSON API(컨테이너 2개), PostgreSQL 테이블 + JSONB, NCP 서버 1대 + 관리형 DB + CDN, 테라폼 필수, 담당자 계정 로그인. CI/CD 는 GitHub Actions(GoCD 보류, 16). ADR 0001~0004
- [본선 시연 시나리오와 발표 구성](issues/08-demo-scenario.md): 10분 배분(시연 4분), 실제 주소 라이브 + 녹화 백업, 담당자 입력부터 기부 전 확인, 수령, 현황판까지 한 이야기. 실제 시설 + 가상 요청. 확장성은 CI/CD 화면, 인프라 코드 복제, 위젯 한 줄로
- [플랫폼 발급 NCP 계정에서 API 인증키 발급 가능 여부 확인](issues/15-ncp-api-key.md): 접근 불가. ncloud 테라폼 불가, 대안은 17
- [NCP API 키 없이 인프라를 코드로 관리하는 방법](issues/17-infra-as-code-without-api-key.md): 테라폼 코드를 기준으로 작성하고 콘솔에서 그대로 생성 후 대조. 코드는 validate 까지, 키를 받으면 import. 서버 안은 Ansible/cloud-init, DNS 는 cloudflare 테라폼 apply
- [CI/CD 도구 선택(GoCD 보류)](issues/16-gocd-team-consent.md): GoCD 는 지금 채택하지 않음. CI/CD 는 GitHub Actions + NCP 자체 실행기, 수집은 앱 안 스케줄. GoCD 는 여유 목록, 이후 재검토
- [3주 개발 일정과 역할](issues/09-schedule-roles.md): W0 환경 구성(이번 주 착수) -> W1 배포된 tracer bullet(11/17 교류회 시연) -> W2 배정과 기부 -> W3 오프라인, 평시, 사용성 테스트 -> 발표 준비. 작은 티켓 큐에서 손이 빈 사람이 가져가는 pull 방식, NCP 콘솔과 정답 표 검수만 담당 지정
- [채움 팀에 배정된 민간 클라우드(CSP) 확인](issues/10-confirm-csp.md): NCP 사용 확정(10/28). 콘솔은 대표자만 접속
- [공공데이터 연동 범위](issues/06-public-data.md): 연동 가능한 것은 이재민 임시주거시설 조회 API(15139148) 하나. 시설, 위치, 수용 인원은 있고 품목과 수량은 없음. 통합대피소는 수용 인원 없음, 구호상황보고와 물자재고는 대피소와 연결 불가
- [분류 모델(C안)을 실제로 넣을지](issues/05-classifier-model.md): laya 는 fp32 ONNX 가 이미 있으나 상주 메모리 2GB대, 지연 미측정. JVM 직접 탑재는 비권장, 규칙 보강 -> 소형 모델 -> Python 사이드카 순. 채택 여부는 02, 형태는 03
- [NCP 배포 구성과 승인 상태](issues/04-ncp-deploy.md): 2026-07 안내상 NCP, KT 는 신규 발급 중단, NHN Cloud 만 가능. 팀당 계정 1개, 대표자만 접속, 클라우드 AI 상품 금지. 실제 배정 CSP 는 NCP 로 확정(10)
