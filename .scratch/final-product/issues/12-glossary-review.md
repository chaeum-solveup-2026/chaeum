# 12: PoC 용어집 검토와 본선 용어 확정

Type: grilling
Status: resolved
Blocked by: None (can start immediately)

## Question

PoC 용어집(chaeum-poc/GLOSSARY.md)의 용어를 본선 제품에 그대로 가져가도 되는가? 각 용어의 정의, 피할 말(_Avoid_), 목업(성은님)과 상세기획서에서 쓰는 말과 어긋나는 곳은? 예: 부족 목록, 남은 수량, 확인 큐, 보류, 대피소 코드, 원문, 해석기, 화면 출구와 데이터 출구. 본선 용어집(chaeum/GLOSSARY.md)에 확정본을 옮긴다. 배정 단계 같은 새 용어는 기능 범위(02)에서 정한다.

## Answer

2026-10-28 grilling 으로 결정(찬규님). 확정본은 이 저장소의 GLOSSARY.md.

- 확인 단계를 목업(S2) 방식으로 통일: 신뢰도 구간을 자동 반영 / 확인 권장 / 확인 필수로 부르고, 권장과 필수 모두 확인 화면에 보인다. 필수는 고치기 전 확정 불가. PoC 의 "확인 큐"와 해석 쪽 "보류"는 없앤다. 구간 경계 수치(0.85, 0.60)는 담당자 화면에 보이지 않게 한다(구간 이름과 색만)
- "보류"는 기부 전 확인에서 보내기 전에 멈춘 물품만 뜻한다
- "남은 수량"을 "부족 수량"(요청 - 배정 - 수령)으로 바꾼다
- 상위 용어 "현장" = 대피소(재난) 또는 배분 거점(평시)
- 담당자와 기부자를 정의했다
- 설계 용어(화면 출구, 데이터 출구, 분류 모델 슬롯, 수신 어댑터)는 용어집에서 빼고 아키텍처(03)의 ADR 로 옮긴다. 사용자에게 보이는 "입력 경로"는 남긴다. 대피소 코드 정의에서 구현 설명을 지웠다
- 나머지 PoC 용어와 기능 범위(02)에서 추가한 용어는 그대로 가져가되, 부족 목록과 요청의 정의를 현장, 배정, 부족 수량에 맞췄다
