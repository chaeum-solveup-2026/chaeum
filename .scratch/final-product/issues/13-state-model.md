# 13: 상태 모델: 요청, 배정, 기부 약속, 배송 중, 수령, 보류, 배분 거점

Type: grilling
Status: resolved
Blocked by: None (12 해결됨)

## Question

기능 범위(02)에서 넣기로 한 배정 단계, 기부 전 확인, 평시 모드를 하나의 상태 모델로 어떻게 묶는가? 품목 줄의 상태 전이(요청, 확인 권장, 확인 필수, 배정, 배송 중, 수령)와 수량 계산(부족 = 요청 - 배정 - 수령), 기부 약속이 배정이 되는 시점과 취소, 대피소와 배분 거점의 관계, 오프라인으로 기록된 요청의 중복 제거는 어떻게 정하는가? 아키텍처(03)의 데이터 저장 결정에 앞선다.

## Answer

2026-10-28 grilling 으로 결정(찬규님).

- 품목 줄(현장 x 품목)은 수량만 가진다: 요청, 배정, 수령. 부족 = 요청 - 배정 - 수령
- 배정은 "아직 도착하지 않은 수량"이다. 수령을 확인하면 그만큼 배정에서 빠지고 수령으로 옮겨 간다
- 상태는 배정 단위로 둔다: 약속됨 -> 배송 중 -> 수령 완료, 또는 취소. 품목 줄 자체에는 상태가 없다
- 기부 약속은 담당자 승인 없이 즉시 조건부 배정이 되고, 정해진 시간(예: 72시간, 값은 설정) 안에 배송 중이 되지 않으면 자동으로 풀려 부족으로 돌아간다
- 약속이 부족보다 많으면 부족까지만 배정하고 나머지는 보류로 돌려 다른 현장이나 현금 기부를 안내한다
- 같은 품목의 새 요청은 기존 요청에 더한다. "충분" 해석은 확인 권장으로 보내고, 확정하면 요청을 배정과 수령의 합으로 줄여 부족을 0 으로 닫는다
- 오프라인 기록은 기기에서 만든 고유 키로 중복 제거한다(붙여넣기와 엑셀의 원문 기준 중복 제거와 같은 원리)
- 평시 모드는 현장의 유형이다. 대피소와 배분 거점이 동시에 운영되고 화면과 공개 목록은 유형으로 거른다
- 배정 없이 도착한 물품은 수령으로 바로 기록하되 요청을 넘을 수 없다. 넘치는 수량은 거부하고 목록 외 수령으로 안내한다
